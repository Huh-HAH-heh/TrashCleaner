# Доработка собственного TrashCleaner

Здесь не рассматривается учебное ТЗ. Цель — сохранить исходный TrashCleaner как личный инструмент и убрать его технические недостатки.

## 1. Главная проблема: rglob()

Сейчас используется `targetDir.rglob("*")`. Это рекурсивный обход.

Из-за этого файл внутри `Projects/` тоже может быть вытащен наружу и перемещён. Для личного инструмента сначала определи два режима: обычный — только текущая папка; рекурсивный — всё дерево.

Если нужен только текущий уровень, вместо `rglob()` можно использовать `iterdir()` или `os.listdir()`.

## 2. Коллизии имён

Сейчас `newPath = newDir / file.name` и затем `rename()`.

При существующем файле возникает ошибка. Сделай отдельную функцию, которая получает каталог и имя файла и возвращает свободный путь.

Логика:

1. Проверить исходное имя.
2. Если занято — разделить имя на basename и extension.
3. Проверять `name_1.ext`, `name_2.ext`, `name_3.ext` и так далее.
4. Вернуть первый свободный путь.

Не добавляй суффикс после расширения.

## 3. Отдели классификацию от перемещения

Сейчас расширение напрямую становится именем каталога.

Лучше иметь отдельный этап:

имя файла → расширение → классификатор → категория → путь назначения

Например несколько расширений могут возвращать одну категорию `Images`.

Плюс это позволит позже менять правила сортировки, не трогая код перемещения.

## 4. Расширения — не всегда такие простые

`Path.suffix` у `archive.tar.gz` даст `.gz`.

Подумай, устраивает ли это лично тебя. Для более сложного определения доступны `Path.suffixes`.

Отдельно стоит решить поведение файлов без расширения и имён вроде `.gitignore` или `.env`.

## 5. Не смешивай ошибки программы и ошибки файловой системы

Сейчас стоит `except Exception`.

Для операций с файлами лучше ловить `OSError`. Слишком широкий `Exception` может скрыть настоящую ошибку в логике программы.

Идея:

ошибка файловой системы → обработать и продолжить

ошибка программирования → дать её увидеть и исправить

## 6. Повторный запуск

Продумай поведение, если каталог уже содержит результаты предыдущего запуска:

Images/
Documents/
Audio/
Video/
Archives/
Other/

Особенно важно это становится при рекурсивном режиме: нельзя случайно разбирать собственные каталоги результата обратно.

## 7. Ссылки

Продумай, что делать с symbolic links, junctions и другими специальными объектами файловой системы.

Для безопасного cleaner полезно иметь явное правило: обрабатывать только обычные файлы или отдельно учитывать ссылки.

## 8. Dry run

Это, пожалуй, самое полезное развитие.

Добавь режим вроде `--dry-run`, в котором программа ничего не меняет, а только показывает план:

photo.jpg → Images/photo.jpg
book.pdf → Documents/book.pdf

После проверки можно запускать реальное перемещение.

## 9. Отчёт

Один `MCount` быстро перестанет хватать.

Полезные счётчики:

found — найдено файлов
moved — реально перемещено
conflicts — пришлось менять имя
skipped — сознательно пропущено
failed — не удалось обработать

И отдельно статистика по категориям.

## 10. Контракт CLI

Твой `argparse` здесь вполне уместен. В дальнейшем можно расширить интерфейс:

`organizer [path]`
`organizer [path] --recursive`
`organizer [path] --dry-run`
`organizer [path] --verbose`

Это уже полноценный маленький CLI-инструмент, а не одноразовый скрипт.

## 11. Почему не нужно переписывать всё сразу

Лучше эволюционировать текущую программу маленькими изменениями:

1. Коллизии.
2. Классификация.
3. Режим обхода.
4. Dry run.
5. Отчёт.
6. Дополнительные CLI-режимы.

После каждой правки запускай программу на отдельной тестовой папке.

## 12. Хороший тестовый набор

Сделай папку, в которой одновременно есть:

один обычный JPG
JPG с верхним регистром расширения
два файла с одинаковым именем
PDF
архив `tar.gz`
файл без расширения
скрытый файл
подкаталог с файлами
уже существующий каталог категории
занятое имя в каталоге назначения

Так ты увидишь реальные слабые места алгоритма.

## Итог

Не переписывай TrashCleaner с нуля. Твой текущий код уже даёт хороший каркас.

Главные вещи для самостоятельной доработки:

`rglob()` → осознанный режим обхода
`newPath` → безопасное разрешение коллизий
расширение → отдельный classifier
`Exception` → более точечная обработка
`MCount` → нормальный отчёт
реальный перенос → `--dry-run` перед изменением файлов

Цель — не сделать код более сложным. Цель — сделать поведение инструмента предсказуемым и безопасным.
